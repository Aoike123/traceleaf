## 1. 阶段 1：ModelGateway（当前下一步）

### 最小边界

- [ ] 明确 ModelRequest、ModelResponse、CallAttempt、ProviderRoute、Usage 的最小契约。
- [ ] 区分逻辑请求、实际网络尝试和上层任务；网关不依赖完整 TaskSpec。
- [ ] 明确结构化输出与 Tool Calling 两条归一路径；工具提议返回上游，不执行。
- [ ] 建立提供商适配边界及可控假提供商，选择一个真实提供商完成兼容性验证。
- [ ] 最小工程、凭证注入、脱敏、配置、请求关联 ID 与日志随网关建立。

### 生命周期与调度

- [ ] 明确准入、等待、派发、接收、归一、结算与交付的状态。
- [ ] 限流按实际共享配额范围计量，不假设每个 API Key 独立。
- [ ] 同时区分请求速率、Token 速率、在途并发和账户余额；不把所有 429 都当作同一种可重试故障。
- [ ] 退避遵守提供商指示，并设置最大尝试、截止时间和排队上限。
- [ ] SDK 内部重试关闭或纳入统一尝试记录，避免重试倍增。
- [ ] 区分排队取消、发送后取消与实际供应商停止；超时不能直接判定没有费用。
- [ ] 用量记录区分预估、确认和未知；重试关联原请求但单独记录尝试与费用。
- [ ] 同幂等键同输入复用既有结果，不同输入冲突；不假定供应商天然支持幂等执行。
- [ ] 结构错误、拒绝、截断交回上游处理，修复属于新逻辑请求；初版不自动换模型。

### CLI 与验收

- [ ] 提供 `gateway request` 和调用记录查询，不先开发完整任务命令。
- [ ] Structured Output 与 Tool Calling 均能返回统一结果及用量。
- [ ] 假提供商覆盖限流、过载、永久错误、超时、取消、无效输出和未知费用。
- [ ] 并发提交网关请求时不绕过准入、在途限制或共享配额；不涉及业务 Task 并行。
- [ ] 每次网络尝试有可核对记录；发送后结果未知时不直接释放全部费用预留。
- [ ] JSON 输出可解析，密钥不进入模型正文、日志或导出。

调用记录需要可查询；可先持久保存最小网关记录，不要求任务树表、全局预算账本或外部操作恢复全部到位。具体存储实现随网关最小契约确定，不将完整数据库设计作为启动前提。

## 2. 阶段 2：能力注册与装配

- [ ] ToolRegistry 描述工具名称、Schema、版本、资源效果与执行绑定。
- [ ] SkillResolver 解析简介、正文、版本和内容哈希。
- [ ] CapabilityBinder 检查能力选择、权限范围、依赖与版本。
- [ ] 实现本地/HTTP 适配边界及一个真实 MCP 的发现与受控调用。
- [ ] ToolExecutor 校验参数和权限，记录操作意图、结果与资源版本。
- [ ] 使用明确输入独立验证能力，不依赖 LLM 自动选择工具。
- [ ] CLI 能查看、检查能力配置；只读诊断不修改业务资源。

此阶段的独立工具验证不等于生产任务树已支持恢复；外部结果未知时必须明确报告，不能盲目重试写入。

## 3. 阶段 3：单 Task Loop

- [ ] 定义最小任务目标、输入、交付、完成条件和单 Loop 限制。
- [ ] 使用固定 Skill/Tools 和受控的小任务，建立 TaskRunner。
- [ ] 串联最小 ContextBuilder、网关、工具执行和候选结果提交。
- [ ] 使用已有 Schema、程序检查和操作记录，不等待完整验证层开发。
- [ ] 验证模型自主选工具、观察、错误修复与步数耗尽；失败明确返回。
- [ ] 任务与必要历史落库；大型内容保存为产物引用。

完整验收策略、树级预算和上下文管理分别在阶段 6、7、9 补齐，本阶段不提前声称全部完成。

## 4. 阶段 4：串行任务树

- [ ] 根任务记录唯一活跃节点与执行权版本。
- [ ] 先用脚本化委派，创建子任务目标、显式输入、固定能力与结果返回位置。
- [ ] 父任务挂起后子任务才可运行；子任务交付并释放后父任务恢复。
- [ ] A 返回父任务后，再决定是否执行 B，禁止同根双活跃。
- [ ] 子任务不自动读取父任务和兄弟完整历史。
- [ ] 失败、输入缺失和重复通知均有明确处理。

模型自动拆解属于阶段 8，不作为本阶段验证执行权交接的前提。

## 5. 阶段 5：持久化与恢复

- [ ] 整合早期记录，补齐 SQLite 任务状态、检查点、修订和关键事件事务。
- [ ] 区分 planned、in_flight、succeeded、failed、unknown。
- [ ] 关键位置退出后，根据幂等标识或状态查询核对未知操作；无法核对时暂停。
- [ ] 重启定位当前节点、等待原因、执行权及未确认外部操作。
- [ ] 过期执行者不能提交；未协调的 CLI/桌面不能重复推进同一工作目录。
- [ ] 建立安全停止和恢复的内部机制，完整用户控制接口在阶段 12 统一。
- [ ] 文件内容与数据库元数据可核对，数据库事务不跨越外部调用。

故障注入：保存操作意图后、外部执行后结果落库前、子任务交付后父恢复前、旧执行者失权后提交、停止请求到达时操作仍在途。

## 6. 后续阶段的衔接

阶段 6–12 按项目计划依次完善验证、预算、拆解、上下文与产物、执行环境、可观测评测和用户控制。各阶段验证前面模块的集成，必要修正由明确缺陷驱动，不改变既定顺序。

阶段 1–5 交付代码时同步提供运行说明、必要测试、演示输入和已知限制。本轮只修订文档，不开始运行时代码。
