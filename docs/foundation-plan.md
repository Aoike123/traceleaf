# Traceleaf 地基实施清单

- 更新日期：2026-10-16
- 状态：待实施
- 阶段定义以 [项目计划书](project-plan.md) 为准；本清单细化阶段 1–3
- 技术依赖见 [技术选型](tech-stack.md)，运行语义见 [体系架构](architecture.md)

CLI 的模块与命令清单见 [CLI 模块计划](cli-plan.md)，本清单负责核心运行时验收。

## 1. 阶段 1：单 Task 闭环

### 设计入口

- [ ] 选择一个可独立验证的小任务与受控输入工程。
- [ ] 定义两个本地工具：明确读取、修改或输出行为与结果。
- [ ] 定义目标、交付物、完成条件及单 Loop 限制。
- [ ] 标明最小状态转换、模块调用顺序和错误分类。

### 实施交付

- [ ] TS workspace、CLI 与独立核心入口。
- [ ] Zod/JSON Schema 最小契约与身份关联。
- [ ] SQLite 迁移、任务与事件存储、本地 ArtifactStore。
- [ ] 固定版本 Skill 和 Tools 装配，ContextBuilder 与输入快照。
- [ ] 一个真实模型适配器，验证结构化输出和工具调用。
- [ ] 可控假模型与假工具，用于错误与停止分支验证。
- [ ] TaskRunner、参数权限校验、基础验收、操作与用量记录。

### 验收

- [ ] 正常任务交付有证据的结果。
- [ ] 无效模型输出、工具失败、权限拒绝与步数耗尽有明确结果。
- [ ] 大型结果保存为产物，不无限追加到模型输入。
- [ ] 密钥不出现在模型输入、日志或产物元数据中。

阶段 1 数据需持久保存，但可靠中断续跑在阶段 3 完整验收。阶段 1 就记录操作意图和实际状态，为阶段 3 补齐协议。

## 2. 阶段 2：串行递归

- [ ] 根任务记录唯一活跃节点与执行权版本。
- [ ] 创建子任务时绑定输入、能力、完成条件与结果返回位置。
- [ ] 父任务挂起后子任务才可运行；子任务释放执行权后父任务恢复。
- [ ] 父任务消费结果摘要、证据和产物引用，不自动继承完整历史。
- [ ] A 返回父任务后，由父任务审查并决定是否创建 B。
- [ ] 重复完成通知不重复汇总或恢复。
- [ ] 子任务失败、无法判断或需要输入均能返回明确状态。

验收任务：根 Task → A 检查 → 父审查 → B 修正 → 父最终验收。记录每次执行权交接，验证不存在同根双活跃节点。

## 3. 阶段 3：恢复与控制

### 故障注入位置

1. 保存操作意图后、真正发出调用前。
2. 外部写入完成后、结果落库前。
3. 结果落库后、父任务恢复前。
4. 旧执行者失去执行权后尝试提交。
5. 暂停或取消到达时，外部操作仍在进行。

### 必须通过

- [ ] 区分 planned、in_flight、succeeded、failed、unknown。
- [ ] 根据幂等标识或资源查询核对未知结果；无法核对时暂停待处理。
- [ ] 重启后定位当前节点、等待原因与有效执行权。
- [ ] 同一工作目录不允许未协调的 CLI/桌面运行时重复推进。
- [ ] 过期执行者不能覆盖内部状态，重复领取不能重复提交结果。
- [ ] 资源版本变化后拒绝基于旧版本的修改。
- [ ] 暂停阻止后续动作；恢复重新检查等待条件和未确认操作。
- [ ] 取消保留已完成副作用，不被描述为回滚。
- [ ] 预留、结算、释放幂等；未知费用不直接释放。
- [ ] 单 Loop 限制与用户整体上限分别处理；上限不足可暂停续跑。
- [ ] 无进展和步数耗尽不自动变成相同任务的无限递归。
- [ ] 检查点保留事实来源、不确定性、未解决项和待确认操作。

## 4. 共同验收与交付

- [ ] 子任务无法隐式读取无关父任务或兄弟历史。
- [ ] 隐藏工具定义不代替执行权限检查；Skill 或工具结果不能扩大授权。
- [ ] 格式正确但目标未达成时，不能进入成功状态。
- [ ] SQLite 状态与关键事件事务提交，外部调用不占用长事务。
- [ ] 产物内容与数据库元数据可核对，孤立文件有处理办法。
- [ ] 可导出任务树、操作、用量、产物依赖和验证证据。
- [ ] 提供运行说明、演示输入、故障恢复说明和已知限制。

进入下一阶段前，只修复阻止该阶段验收的具体问题，不提前实现完整 RAG、Workflow 提取器或商业服务端。
